## Existing contract and actual entry point

Inspected InstitutionResource, its registered CreateInstitution page, InstitutionForm, InstitutionPolicy, Institution model guards, StaffListScope/ScopeAuthorizer, CoreIdentityObserver and its AppServiceProvider registration, AuditRecorder and installed Filament CreateRecord/CanUseDatabaseTransactions.

- Create policy requires active identity and explicit `institutions.manage`; ordinary staff HTTP admission separately requires panel access. No role-name bypass. The diagnostic actor has existing `platform.admin.access`, `institutions.view` and `institutions.manage`, not a new permission or role.
- The form accepts required name (maximum 255), optional official ID (maximum 255, unique), optional primary region through the existing scoped relationship query, and required active/inactive status. Region options use `StaffListScope::regions(..., 'institutions.manage')` and effective regional/nationwide authority. The model's **creating** guard separately rejects a nonnull region outside `ScopeAuthorizer::canAccessRegion`. K1's current-institution Update contract is not imported.
- The form exposes neither organization type nor synthetic flag. Defaults remain `hei` and `false`; public UUID is generated by the model. No institution row creator column is assigned by this form; creation attribution is the existing Core audit's actor. No representation, eligibility, account activation or user scope grant is created here.
- The actual page inherits `CreateRecord::handleRecordCreation`, performing a real Eloquent save. Registered CoreIdentityObserver then writes the sole existing **`App\Models\Institution.created`** event, success outcome, current actor/resource, institution and selected region. Recorded creation metadata is `changed_fields: []`; no new metadata semantics are inferred.
- No operation-owned transaction exists on this Create path. The actual mounted page reports optional transactions disabled. Installed Filament calls begin/rollback helpers, but these return without database operations when disabled. AuditRecorder inserts on the normal connection and owns no encompassing institution transaction. K1's separate Update service does not handle Create.

## Fixtures and diagnostic method

These are wholly fictional, transaction-cleaned test records in osds_test, not real institutional data or manual-testing records.
