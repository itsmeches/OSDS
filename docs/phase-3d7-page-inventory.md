## 10. Batch B design-system proposal

1. Keep the approved navy/blue identity. Add semantic action background/foreground/hover pairs independently from link colors in both themes. Source-token calculations show white on dark-mode blue-700 at **2.13:1** and blue-600 at **2.77:1**; these are screening calculations, not measured rendered colors.
2. Standardize body/form text at 1rem with 1.5 line-height, normal supporting text at .875rem, and meaningful headings. Reserve smaller text for nonessential metadata; do not globally override Filament control mechanics.
3. Establish shared surface, stacked card, heading/action row, field/help/error, status, notice, empty-state, and progress patterns. Apply scoped classes rather than styling every descendant span/card identically.
4. Standardize borders, visible focus, action target sizes, and normal/hover/focus/error/pending/disabled states. Use icon/text alongside status colors. Keep action confirmation, persistence, and domain permissions unchanged.
5. Align applicant and Filament colors/spacing through shared tokens. Replace hardcoded light-only preview/home colors; preserve Light/Dark/System preference and prevent theme flash where supported.
6. Establish browser verification in a dedicated disposable database before accepting B's visual gate. Use Playwright/axe when available; capture safe representative screenshots and measure actual computed colors. Test 320/375/768/1024/1440px, keyboard, reduced motion, 200%/400% reflow. Mark any unavailable check unverified and retain the contrast release blocker.

Batch B's design changes are proposed here; no visual refinements were implemented in this security-fix update. The remaining A–H gates and the final refinement report/manual retesting guide are still required before a final readiness verdict.
