# OSDS Form Maker 2.0 usability test

**Status:** Prepared; testing with actual OSDS personnel is pending
**Test data:** Synthetic configurations and identities only

## Participant profile

Invite an OSDS employee who can browse websites and enter data but has not used the questionnaire configuration screens. Do not explain internal versions, keys, hashes, or database concepts before the test.

## Scenario

Ask the participant to prepare a synthetic Registration questionnaire:

1. Open **Questionnaires**, select Registration, and create a questionnaire named “Synthetic Sports Registration”.
2. Add short answer, paragraph, multiple-choice, checkbox, and date questions.
3. Add at least two choices to each choice question.
4. Reorder one question and duplicate another.
5. Add a question that appears only when an earlier answer has a selected value.
6. Select **Test form**, answer the earlier question, and confirm the conditional question appears.
7. Add two document requirements and select accepted link types.
8. Save the draft, leave the page, reopen it, and confirm the content remains.
9. Create a validation error by removing a choice, run **Check form**, and correct the identified problem.
10. Run **Check form** again and send the exact configuration for Admin review.
11. Explain what the interface says will happen next.

## Accessibility prompts

- Repeat the primary path using only the keyboard.
- Confirm visible focus and meaningful control names.
- Test browser zoom at 200%.
- Test a narrow viewport around 320 CSS pixels.
- Switch between Light, Dark, and System modes.
- Enable reduced-motion preference and confirm the workflow remains understandable.

Do not record a usability success claim until actual participants complete the scenario and the observations are documented.
